# ПАРИТМ — мастер-ТЗ и паспорта экранов (v1.0)

## Назначение и архитектура
ПАРИТМ — независимое от TERENSAI офлайн Android-приложение для банных сценариев: план, факт, активный этап, архив, отчёты, конструктор и аналитика. Корпоративные сценарии — отдельные проверенные templates. Хронометраж организационный, не медицинское предписание.

**Архитектура:** `Jetpack Compose → ViewModel/StateFlow → Domain (Clock, ProgramPlan, SessionPlan, TimelineEngine) → Repository → Room/SQLite`. Отдельно платформенные Android адаптеры для notifications, sound, backup и Sharesheet. UI не считает бизнес-время отдельно. При создании сессии сохраняется immutable plan snapshot и event log с устойчивыми ID.

## 10 утверждённых макетов и их кодовые контракты

| ID | Название | Информация / главные действия | Итерация |

| S02 | Программы | плитки и статус template; исполнимый → S03, draft только preview | B1 |
| S03 | Подготовка сессии | номер сьюта (optional), старт, параметры, проверка, одна сессия → S04 | B2 |

**S01** — системный splash отдельно от фирменной стартовой страницы. **S05** — 2 ориентации *одного* экрана. Диалоги/шторки не увеличивают количество главных страниц: ProgrammePreview, QuickActions, ConfirmFinish, SoundPicker, PermissionExplainer, BackupRestore, ReportPreview.

## Подтверждённые общие сроки
Танысу 180 мин (три коллективных парения по 10–15 мин), Light 240, Grand 240, Premium 300, Supreme 300. Детальные stage offsets не утверждены. Select, Orda, Tan Light, Special известны по названию, длительности неизвестны. До уточнения нельзя показывать их как исполнимые шаблоны с выдуманным временем. Нормализация LITE/Light и SUPRIM/Supreme — открытый вопрос.

## Слои и рабочие модели
- `ProgramTemplate` (status/source/version), `StagePlan` (stageId, track, startOffset, plannedDuration, kind), `Session` (sessionId, immutable templateSnapshot, startedAt, state), `SessionEvent` (idempotency key, kind, at, stageId), `ReminderRule`, `SoundPreset`.
- `Clock` — инъекция и FakeClock для тестов; для устойчивости при ручной смене системного времени требуется расширение wall+monotonic и отдельные тесты.
- Room: sessions/programs/events, план миграции схемы, без `fallbackToDestructiveMigration`.
- Дорожки GUEST и MASTER могут идти параллельно, wall elapsed не суммируется дважды.
- Обязательные отображаемые состояния: first launch, loading, empty, active, paused, overtime, skipped, completed, error, permission-denied.

## Внешний вид
Фиксированные токены из [Design System 1.0](../design-system/DESIGN_SYSTEM_1.0.md), но не целый снимок экрана в качестве фона. Главные кнопки ~64dp; доступные зоны ≥48dp; русский текст, системные insets и fontScale 1.5.

## Особые правила из утверждений
- S05 portrait: реальное HH:mm слегка прозрачно **по центру НАД центральным таймером**; landscape: справа возле него.
- S06: Т, L, G, P, S, Se, Sp, O, TL внутри бронзовых медальонов, полное имя текстом.
- S04↔S05 навигация и Android Back **не изменяют** статус этапа; пауза этапа **не останавливает** общие часы.
- S04 — глобальное отклонение/прогноз; S05 — локальный остаток/перерасход. Ярко-оранжевый для действительного превышения, зелёно-бирюзовый для факта.
- Никакого автоматического экспорта персональных данных: WhatsApp через системный Sharesheet только по действию пользователя.

Этап считается готовым только после CI, реального сохранения данных, установки APK и проверки на Xiaomi 13T Pro.
