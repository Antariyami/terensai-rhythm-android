# Android signing policy for ПАРИТМ

## Не смешивать тестовые APK и постоянные релизы

Текущий `v0.1.0-test` опубликован с временным debug-ключом GitHub Runner. **Не обновлять этот APK тем же тегом** после новых коммитов. Пользователь может потерять возможность обновления поверх установленной версии из-за несовпадения сертификата.

1. До коммерческого релиза согласовать бренд и неизменяемый `applicationId`; сейчас это `kz.terensai.rhythm`. Если переходим на нейтральный ID, это будет фактически другая Android-программа.
2. Владелец проекта самостоятельно генерирует release-keystore на доверенном компьютере Android Studio / JDK, выбирает стойкий пароль, хранит **две защищённые резервные копии** вне репозитория.
3. Никаких ключей, .jks, .keystore, паролей или base64 ключа в GitHub-коде, Issues, чатах и логах. Добавить соответствующие шаблоны в .gitignore.
4. GitHub Actions: для будущей release-сборки использовать `Environment: production` с ручным approve, защищённые GitHub Actions Secrets, секретный файл декодировать только внутри job и удалить после сборки. Нельзя печатать его содержимое.
5. Разделить workflow `build-debug.yml` (автоматическая проверка) и `publish-release.yml` (вручную и только после тестов). Теги и номера версии неизменяемы.
6. Тестировать установку, обновление, экспорт/восстановление данных и переход с v0.1. Нельзя обещать обновление поверх v0.1, подписанной другим debug-ключом.
7. В новой версии включить экспорт архива до любого действия, при котором потребуется удалить старую установку.
8. Проверить условия распространения через Google Play или прямой APK и юридические права на дизайн, исходники и шаблоны.
