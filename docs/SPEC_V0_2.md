# ПАРИТМ — спецификация v0.2 (13.10.2026)

> **Статус:** утверждено направление продукта и дизайн-концепция; этот документ — требования, **не реализованный код**.
> **Бренд:** ПАРИТМ · «Ритм банного мастерства» (рабочее название до проверки товарного знака).
> **Платформа:** Xiaomi 13T Pro / HyperOS, офлайн Android; позже планшет и большой экран.

## Зафиксированный UX
1. Быстрый splash с адаптивной иконкой часов и дубовых веников, кнопки «К программам» / «Продолжить».
2. **Плитки программ** с длительностью, количеством заходов, происхождением шаблона и статусом его нормативов.
3. **Ход программы:** текущее время, время до планового конца, большой таймер этапа, постоянная шкала **ПЛАН / ФАКТ / ПРОГНОЗ**, быстрые действия, следующий этап.
4. **Режим фокуса:** только часы, активная процедура и огромная кнопка; экран планшета/монитора затем read-only.
5. **Архив:** история независимых сессий с датой, программой, планом, фактом, журналом изменений, копированием мини-отчёта и Android Share Intent для WhatsApp.
6. **Редактор** собственных сценариев после надёжного ядра версии 0.2 (версия 0.3).

Цвета: background `#15110F`, surface `#281E1A`, amber `#F2A047`, bronze `#C69B66`, text `#F6F1E8`, positive `#95AC8C`, alert `#D27658`. Кнопки крупные (48dp+), основное действие 60–72dp. Цвет не должен быть единственным индикатором состояния.

## Библиотека по имеющимся прайсам
- **Танысу** 180 мин, 3 коллективных парения по 10–15 мин.
- **Light / LITE** 240 мин, бесконтактный прогрев + индивидуальное парение.
- **Grand** 240 мин, 2 коллективных парения.
- **Premium** 300 мин, коллективное + индивидуальные + SPA и массаж.
- **Supreme / SUPRIM** 300 мин, индивидуальное парение в три этапа и SPA.
- **Select, Orda, Tan Light, Special**: названия известны, но рамки и процедуры требуют подтверждения.
Длительность услуги не приравнивать к непрерывной тепловой нагрузке. Неподтверждённые этапы маркировать как «Черновик».

## Техническая логика
- Шкала плана фиксируется снимком шаблона при создании сессии; редактирование шаблона не меняет старые сессии.
- Фактическая линия создаётся событиями; план/факт/прогноз — отдельные вычисляемые модели.
- События: SESSION_STARTED, STAGE_STARTED, STAGE_PAUSED, STAGE_RESUMED, STAGE_COMPLETED, STAGE_SKIPPED, STAGE_ADDED, PLAN_ADJUSTED, EVENT_CORRECTED, SESSION_FINISHED.
- Быстрые изменения маршрута (пропустить, добавить, сдвинуть, продлить) фиксируются как события и пересчитывают будущие напоминания. Двойные нажатия идемпотентны.
- Пауза текущего этапа не останавливает общий ход времени. После блокировки/возврата восстанавливать по сохранённым меткам; изменения системных часов обнаруживать.
- Отдых гостей и уборка/подготовка/отдых мастера — **параллельные дорожки**, минуты не суммируются дважды.
- Хранение офлайн, архив независимых сессий, JSON backup; WhatsApp через системную кнопку «Поделиться», **без** автодобавления персональных данных гостей.

## Напоминания
- Категории: этап скоро окончится; подготовить парную; пригласить гостей; N минут до конца программы; отдых мастера.
- Четыре аудио-пресета: дерево, мягкий колокольчик, капля, листья; пользователь задаёт звук, вибрацию, громкость, выключение.
- Android POST_NOTIFICATIONS (когда применимо), системные ограничения exact alarms, DND, энергосбережение HyperOS; реализацию и точность подтвердить на физическом Xiaomi.
- Использовать нативные Android API, не полагаться на периодические веб-таймеры при закрытом экране.

## Архитектура / контракты
Текущее состояние v0.1 — один `MainActivity.java` (~161 строка), жёстко заданные этапы, `SharedPreferences`. Это прототип; предстоит **поэтапная** миграция без потери данных.

Целевой стек — Kotlin, Jetpack Compose, ViewModel/StateFlow, Room/SQLite, DataStore, Gradle CI, Android Notifications/Share Intent. На v0.2 допускается **один** Gradle module `:app`, но разделение кода по пакетам:
```
core/time, core/design
domain/program, domain/stage, domain/session, domain/timeline, domain/reminder, domain/usecase
data/room, data/repository, data/migrations
feature/launch, feature/programs, feature/session, feature/archive, feature/settings
platform/notifications, platform/sound, platform/share
```
Направление зависимостей: `feature → domain ← data`. У domain нет Android импортов. Все расчёты времени через интерфейс Clock и FakeClock в JVM-тестах. Immutable snapshot плана + append-only event log + коррекции вместо удаления истории.

Базовые сущности: ProgramTemplate, StageTemplate (track,startOffset,plannedDuration), Session (snapshot), SessionEvent, ReminderRule, SoundPreset. Инварианты: уникальные ID, отсутствие повторного завершения, сохранность предыдущих сессий, отсутствие двойного суммирования параллельных этапов, корректный переход суток.

## Подпись и безопасность
**До подписанной версии** зафиксировать `applicationId` (v0.1 использует `kz.terensai.rhythm`). Release keystore генерирует/хранит правообладатель; ключ и пароли не коммитить; использовать защищённые GitHub Secrets и environment с ручным утверждением. Debug-версия с иным ключом может не обновиться поверх release; до удаления старой установки проверить экспорт данных. Код репозитория сейчас публичный: согласовать приватность, права на корпоративные шаблоны, лицензию и регистрацию бренда.
