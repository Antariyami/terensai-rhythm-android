# ПАРИТМ P2.4 — дополнительные процедуры и события на таймлайне

**Основа:** P2.3 `7cd8bd5d8b8b346cb7d939cc88d15bc018a12271`, PR #49.
**ТЗ:** #41, #47; актуализированный источник меню и программ — #48.

## Scope P2.4
- На активной программе отдельные «+ Процедура» и «+ Событие».
- Услуга выбирается из SPA каталога (15 вариантов с плановыми минутами и коммерческой ценой из скриншотов TERENSAI). Можно выбрать **любого действующего мастера**, роль PM/SPA/PM1, длительность. Создаётся `WorkEntry` в состоянии READY, не завершённая процедура. Отдельные кнопки Начать/Пауза/Продолжить/Завершить; журнал WorkRepository остаётся источником факта. `serviceLabelSnapshot` сохраняет точное название, `procedureType` — прежняя категория для совместимости.
- «+ Событие» — ожидание гостя, техническая задержка, другая причина. Начало и остановка с отметками времени. Галочка постановки текущего этапа на паузу выполняется **в одной Room транзакции** с созданием события; другая дорожка не останавливается. Возможность исправить количество минут с обязательной причиной, сохранением первоначальных событий и времени внесения изменения.
- «+ Дополнительный час» продлевает **только плановую границу** на 60 мин; повтор допустим с отдельным ID и подтверждением. Не меняет immutable ProgramPlan, не создаёт оплату/работу. Справочная цена определяется по сьюту из оригинального маркетингового скриншота.
- Room schema v9, additive `MIGRATION_8_9`: таблица `programme_action_events` + nullable label колонки work_entries. Старые session_events, work_events, checklist_runs не меняются.
- Штатные каталожные карточки LIGHT и GRAND показывают 4 ч, PREMIUM и SUPREME — 5 ч (исходные скриншоты); их **исполнимые маршруты пока НЕ активированы** без согласованной техкарты начала/отдыха/уборки/завершения. В рабочей программе P2.4 доступны пилотная ТАНЫСУ и созданные мастером собственные программы.

## Сохранность и ограничения
- P2.4 APK `kz.paritm.p24.preview` имеет отдельную базу; не удалять N1.1, P2.3 и другие прошлые приложения. Без автоматического переноса данных QA между package ids.
- Планы GRAND/LIGHT/PREMIUM в карточках информативны, тайминги и повторения этапов пока уточняются по техкартам. SUPREME только карточка.
- **Telegram «Сегодня/месяц/6 месяцев» сейчас отражает только подтверждённые парения согласно ранее принятому контракту.** SPA запись хранится в общем журнале и должна быть отдельно согласована для расширенного Telegram-отчёта; не менять прежнюю статистику молча. Задержки не учитываются как услуги.
- «Корректировка фактического времени окончания программы» (не равно продлению плана) остаётся #42/P2.5.
- CI компилирует AndroidTest APK, но **не выполняет** instrumented tests на реальном Android. Приёмка владельцем после Xiaomi — отдельный статус.
