# ПАРИТМ — дорожная карта после испытания B1+ на Xiaomi 13T Pro

Дата: 13.10.2026. Основание: скриншоты пользователя из рабочего APK `v0.2.0-b1-approved-preview-2`. Статус: **обратная связь зафиксирована, исправления ещё не реализованы**.

## Что подтверждено

B1+ устанавливается и запускает два Compose-экрана (приветствие S01 и каталог S02); плитки и возврат работают. Из-за связи `EntryActivity → MainActivity` выбор «Танысу» **специально открывает старый Java-таймер**. Это сохранённый демонстрационный путь, а не реализация нового S04; его замена назначена на B2.

### Визуальные дефекты, блокирующие утверждение B1
- Размытие и квадратные края медальона на стартовом экране: в QA применяется сниженный растровый WebP около 128×128 px, масштабируемый до 208dp. Источник выше разрешением, но финальная Android-развёртка ещё не сделана.
- Фон приветствия — простой Compose gradient вместо утверждённого фото-художественного фона.
- Плитки каталога пока с буквенными медальонами и градиентами, но без утверждённых декоративных изображений и композиции.
- UX-разница между первой парой экранов и старой `MainActivity` слишком велика.

## Принцип оформления — скины по итерациям, а не в конце

**Не делаем всё приложение одной картинкой.** Изображения: фоновые/художественные WebP; функциональные элементы: Kotlin Compose, scalable vector, Canvas, Typography, proper click semantics. Для каждого экрана — отдельный image budget и тест качества на Xiaomi.

Для финального апп-значка: исходник 1024×1024 с проверкой резкости, реальный launcher/mipmap для обычных масок, adaptive foreground/background + monochrome. Учитывать 108dp adaptive grid/66dp safe zone; удалять «двойную квадратную рамку» если маска обрезает эмблему. Не масштабировать 128px до крупного hero-изображения на экране.

Ориентиры после измерений, **не жёсткие гарантии**: декоративный WebP ~150–500KB/фон, миниатюры 40–150KB/плитка, ленивая загрузка. Бюджет ресурсов пересматривается после проверки памяти и загрузки на реальном телефоне. Тексты, кнопки и хронометраж не должны быть частью растрового фона.

## B2: входные данные и недостающие определения

Подтверждены только **общие сроки**: Танысу 180, Light 240, Grand 240, Premium 300, Supreme 300 минут. Детальные длительности каждого этапа — *ещё не согласованы*; для B2 можно создать явно помеченный пилотный редактируемый тайминг «Танысу», но **не выдавать условные минуты за корпоративный стандарт**. Пока не определён норматив этапа, рабочая программа с ним не считается завершённой.

**S04** показывает `wallClock HH:mm`, elapsed всей программы/конец, общую шкалу этапов, общий сдвиг, факт/план и прогноз. **S05** в B3 показывает крупно локальный этап, остаток `max(0,P-E)`, превышение `max(0,E-P)`, следующий этап и кнопки возврата/управления. Пауза активного этапа НЕ останавливает общее астрономическое время программы.

Тесты для B2 обязательны: `12:15 / 15:00 → осталось 02:45`, `17:45 / 15:00 → превышение +02:45`, возврат в каталог и обратно, экран заблокирован, перезапуск, двойной старт, один event log, без разрушительной миграции.

## Критерии поставки и границы

1. После B1.1 — реальный отдельный QA APK, скриншоты пользователя, правка UI до утверждённого оформления.
2. После B2.1/B2.2 — отдельно тестируем сохраняемый двигатель сессий и рабочий экран; не ждать фокуса B3, чтобы получить современный таймер.
3. Новая сборка только после CI, ссылка напрямую на asset `.apk` в GitHub Releases.
4. Временный debug APK с отдельным `applicationId` не заменяет старую 0.1 и может быть подписан другим ключом; для последовательного update и сохранения данных релизного приложения потребуются постоянная подпись и продуманная миграция.
5. PR #9 в статусе draft до устранения визуальных замечаний и подтверждения B1.1 на Xiaomi.
