# ПАРИТМ — B2.4.2a и дальнейшие модули: согласованные решения (14.10.2026)

## B2.4.2a — Сьюты и участие
- Встроенный редактируемый список для новой установки: 1 Көркемдік, 2 Өркендеу, 3 Сәттілік, 4 Байлық, 5 Амандық. Данные существующего пользователя не перезаписывать.
- Справочная вместимость: Көркемдік 4 (фактически может быть 6 с детьми), Өркендеу 6, Сәттілік 6, Байлық 10, Амандық 20. Значение не является жёстким пределом. Фактических гостей включая детей — отдельное поле ручного ввода. При превышении справочного числа предупреждать, но разрешать сохранить; эксплуатационную вместимость утверждает комплекс.
- Пользователь может добавлять/переименовывать/скрывать места работы. Для будущей синхронизации: SuiteEntity со стабильным ID, workspaceId, originClientId, revision; сессии хранят snapshot названия, чтобы изменения справочника не искажали архив.
- «Участвовать в программе другого PM1» = отдельная личная работа с указанием PM1 из справочника (или добавлением), места, названия программы при известности, роли, процедуры, даты/времени начала, плановой и фактической длительности. При наличии своей локальной программы можно выбрать sessionId. Это не должно создавать вторую полную банную сессию. Изменить подпись «Танысу · личный пилот» на «Танысу · тестовый маршрут».
- **Не запускать внешнее участие в production, пока обязательные PM1 / сьют / время не записываются в Room.** Требуется новая миграция Room v4→v5 с отдельной сущностью external programme/work context или корректным nullable workEntry association и snapshot PM1; не хранить единственную связь через UI-строку.
- Для личной процедуры обязательно сохранять ID мастера, ID/снимок PM1, role, procedureType, план, старт/пауза/возобновление/финиш по событиям, suiteId/name snapshot, время и дата, заметку.

## B2.4.2b — Несколько личных процедур
- Незавершённых WorkEntry любое разумное число, одна процедура в RUNNING у одного мастера на одном устройстве (проверка внутри Room transaction при START/RESUME). Остальные READY/PAUSED. Предложить поставить текущую на паузу при старте другой.
- «Мои процедуры» из «Моя смена»: список по статусу; нельзя терять запись, когда создана новая; выбор любой из сохранённых для продолжения. В дальнейшем несколько устройств требуют серверного согласования активного таймера.
- Разрешить документированное перекрытие лишь через отдельное подтверждение/коррекцию отчёта, не добавлять часы дважды в итог занятости.

## B2.4.3 — Журнал
- Фактические работы за сутки, фильтр сьют/PM1/роль, события и история изменений, агрегаты без двойного учёта, экспорт WhatsApp.
- Не удалять оригинальные события при исправлении — append-only correction event с причиной.

## D и D2 — Уведомления и календарь
- D: 4 приятных звука, уведомления по времени этапов, собственные повторно используемые шаблоны «травы», «печи», «отчёт», «подготовить распределение смены».
- D2: компактный календарь на ширину экрана (в том числе landscape), состояния смены PLANNED/CONFIRMED/WORKED/ABSENT/CANCELLED, отметка «не был», 24 ч до смены reminder с настройкой времени, месячные totals planned/actual/missed. Не делать вывод «отработана» только из расписания.

## D3 — План личного дохода
- Личная месячная цель, редактируемые расценки по типам процедур, ставка за смену, бонусы и нерегулярные выплаты, поддержка своей валюты.
- Отдельно отображать начислено по выполненным процедурам, запланировано, остаток до цели и прогноз, без смешения оплаты мастеру и цены услуги для гостя.
- План рассчитывать исходя из типов процедур/ставок и доступных смен; учитывать округление количества процедур вверх, не считать неотработанные смены фактом; показывать расчёт, чтобы пользователь мог его проверить.

## D3 — PIN-защита финансового раздела (добавлено по согласованию)
- Раздел «Мой доход / Финансовый план» закрыт за отдельным 6-значным PIN; пользователь устанавливает и подтверждает его при первом включении.
- Не хранить PIN в открытом виде, в SharedPreferences или репозитории. Предпочесть Android Keystore и зашифрованную базу/секрет для финансов; проверять сценарий компрометации данных при физическом доступе к устройству. Одна блокировка UI без шифрования **не считается защитой финансовых данных**.
- Автоблокировка при сворачивании и по таймауту; ограничение попыток с возрастающей задержкой; при потере PIN — отдельный безопасный сброс финансового хранилища с предупреждением о потере неподтверждённых данных.
- Не включать значения заработка в уведомления, общий экран, историю отчётов и текст шаринга без отдельного действия пользователя.
- Опционально биометрия только после установки PIN; проверить безопасность резервного метода входа и политику Android KeyStore.
- Не объявлять реализацию PIN готовой до security QA, включая тесты резервного копирования, смены устройства и блокировки.
