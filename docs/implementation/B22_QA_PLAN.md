# B2.2 — первый настоящий рабочий таймер ПАРИТМ

**Статус:** тестовая реализация в отдельной ветке, предназначена для приёмки на Xiaomi 13T Pro, не выпуск для работы с реальными гостями без проверки.

## Что изменилось после B2.1

- В тестовой сборке B2.2 плитка **Танысу → Настроить / продолжить** открывает новый `B22SessionActivity` вместо прежнего Java-таймера.
- S03: сьют, число гостей, редактируемые шесть интервалов и автоматически дополняемый завершающий период. Итого строго 180 минут. Параметры записываются вместе с immutable snapshot.
- S04: реальные часы, общее время / план 3 часа, прогнозное плановое окончание, активный этап, локальный таймер и остаток, превышение, единая шкала маршрута и фактического положения, статусы этапов.
- `START/PAUSE/RESUME/COMPLETE/SKIP/FINISH` вызывают транзакционный `SessionRepository`, интерфейс обновляет данные из Room; повторный старт возвращает ту же сессию.
- «К программам» и Android Back **не** ставят этап на паузу; возврат по «Продолжить сессию» восстанавливает этап и ID.
- Пауза этапа останавливает только активное время этапа; ход всей программы продолжается.
- Завершить всю сессию разрешено только после завершения либо пропуска всех этапов, с явным подтверждением.
- Фирменная эмблема, тёплая тёмная атмосфера и палитра ПАРИТМ присутствуют как реальные графические элементы. **Чистые фотографические фоновые assets из художественных референсов ещё не внедрены**; это следующий графический проход, без превращения кнопок/цифр в картинки.

## Важное о нормативах

В этой версии пробный маршрут: встреча 15 мин, парение1 12, отдых1 35, парение2 12, отдых2 35, парение3 12, оставшиеся 59 мин — свободное время и завершение. Это **не утверждённый регламент**; пользователь может изменить первые шесть чисел, остаток пересчитается. Это сделано только чтобы испытать реальную шкалу на 3-часовой программе, не изобретая нормы TERENSAI.

## Протокол приёмки на Xiaomi

1. Установить QA APK B2.2 отдельным приложением `kz.paritm.b22.preview`.
2. «Выбрать программу» → «Танысу» → «Настроить / продолжить». Проверить, что теперь открывается **Подготовка**, а не старый зелёный Java-таймер.
3. Ввести имя сьюта и число гостей (можно не вводить), поменять минуты одного этапа. Убедиться, что окончание автоматически пересчитано и сумма равна 180.
4. «Начать программу». Запомнить текущие часы и первый этап, нажать «Начать этап».
5. Пауза через 10–20 секунд; убедиться, что время этапа остановилось, а общее продолжило идти. Выйти в каталог и вернуться по «Продолжить сессию».
6. Проверить, что ID и параметры восстановились после полного закрытия и повторного открытия.
7. «Завершить этап», перейти ко следующему. При необходимости «Пропустить этап» требует отдельного подтверждения. По последнему этапу — «Завершить программу».
8. Проверить локальный план/факт: если длительность этапа меньше факта — только тогда появляется оранжевое **«Превышение»**; в обратном случае — зелёное «Осталось».

## Что пока не готово

- **B3:** одобренный полноэкранный фокус с большим круговым таймером в portrait/landscape и кнопкой «К сессии».
- **C:** архив сессий, копирование и WhatsApp.
- **D:** звуки и маршрутные уведомления.
- **E:** подписанный неизменным release key APK, резервное копирование, безопасная миграция старых данных.
- **0.3/0.4:** полный универсальный конструктор и аналитика.
- Не протестирована устойчивость к ручной смене системного времени и перезагрузке Android.
- Android instrumentation APK в CI **собирается**, но тесты выполняются только на Android device/emulator.
- Этот тестовый пакет имеет собственную песочницу, поэтому B2.1 не переносит свои данные автоматически в B2.2.

По приёмке B2.2 отдельно фиксируем пиксельный дизайн S03/S04, художественные фоны без текста и маршруты действий перед началом B3.
