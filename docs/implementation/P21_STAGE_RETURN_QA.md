# P2.1 · Возврат на предыдущий этап

Основа: P1.0 `6912b6d7ca784883e038cf9fe4d5e87f8000c6ba` (PR #34; физический QA пока не подтверждён). Новое требование: #36.

## Реализованное поведение
- «Ход программы» → «← Предыдущий этап: название» → подтверждение.
- Новое событие `REOPEN` в `session_events`, без удаления старого COMPLETE/SKIP.
- Накопленные минуты сохраняются; разрыв до возврата не входит в длительность. RUNNING этап той же дорожки атомарно получает PAUSE, другая дорожка не останавливается.
- Повтор операции с тем же commandId не создаёт второго события.
- После завершения возвращённого этапа приписывание парения в S13 учитывает два интервала и одну запись.
- **Ограничение:** если этап уже внесён в личный журнал S13, возврат блокируется: нужна отдельная безопасная синхронизация WorkEntry, иначе отчёт исказится. Нельзя выдавать этот случай за реализованный.
- У завершённой программы возврат не разрешён (отдельная задача #42).

## Хранение / сборка
Room version 7 не меняется: новая разновидность события в существующей таблице. Идентификатор тестовой сборки `kz.paritm.p21.preview` — **отдельная база** от N1.1/P1.0, их APK не удалять. `check-p21-stage-return.yml` выполняет JVM unit tests, собирает APK и **компилирует** инструментальные тесты Android (не запускает их на телефоне). Release без разрешения не публиковать.
