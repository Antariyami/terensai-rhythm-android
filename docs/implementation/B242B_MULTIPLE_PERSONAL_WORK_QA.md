# ПАРИТМ B2.4.2b · QA на Xiaomi 13T Pro

Цель: проверить персональные профили, разделение рабочих процедур и **не более одного таймера RUNNING у одного мастера**. Тестовая сборка с отдельным Android package ID от B2.4.2a; данные предыдущей тестовой версии сами не перенесутся.

## Обязательные сценарии
1. После чистой установки есть Андрей и Олжас; ровно один помечен «МОЙ ПРОФИЛЬ» — Андрей. У Андрея нет кнопки «Сделать моим»; у Олжаса она есть. Переключить на Олжаса и обратно, закрыть и открыть приложение. Не должно возникать дубликатов.
2. С Андреем как личным профилем создать индивидуальное парение в сьюте «4 · Байлық» под PM1 Олжас, план 45 минут. Нажать «Начать».
3. Не завершая и не ставя на паузу первую работу вручную, нажать «+ Новая процедура»; создать массаж, нажать «Начать». **Индивидуальное парение автоматически получает PAUSE, массаж становится единственным RUNNING.**
4. Вернуться к индивидуальному парению и нажать «Продолжить». **Массаж автоматически получает PAUSE**; индивидуальное парение продолжает не с нуля.
5. Полностью закрыть приложение (в том числе выгрузить задачу) и открыть. В «Моя смена → Мои процедуры» видны обе записи и их состояния, не более одной «ИДЁТ».
6. Сделать третью процедуру «Коллективное парение» и перейти к ней; старый RUNNING переходит в PAUSE. Запустить общую программу Танысу. Её этапы и общее время не должны зависеть от личных таймеров.
7. Завершить одну процедуру — она исчезает из активных карточек и попадает в раскрывающийся раздел «Завершённые» S12. Остальные READY/PAUSED/RUNNING не исчезают.
8. Дождаться двух действий в одну секунду (быстрые переключения): журнал START/PAUSE/RESUME/COMPLETE должен верно рассчитывать факт (для действий в одну миллисекунду порядок сохраняется по rowid). Повторное открытие без обнуления.
9. Проверить свежую установку с 2 профилями и существующую базу: выбранный вручную «Мой профиль» нельзя перезаписывать.

## Приёмка
- Никаких одновременно RUNNING личных процедур для *одного и того же staffId* на одном телефоне.
- Любая незавершённая процедура восстанавливается по Room без зависимости от Compose remember.
- У каждого действия отдельное WorkEventRow; автоPAUSE — событие, а не скрытая правка старого времени.
- Раздел «Завершённые» не смешан с текущими задачами. S13 расширенная история/отчёт — следующая итерация.
- JVM unit tests и assembleDebug/assembleDebugAndroidTest в GitHub Actions; сборка instrumentation APK **не означает запуск тестов на физическом устройстве**.
