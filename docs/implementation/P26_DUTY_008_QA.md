# P2.6 + №008 «Дежурство» — объединённая QA

## Код и границы
База: P2.6 `8788726c4ba4f6459bc14fdfc40be676db851800` (PR #51, draft). Новая задача #54. Другие шаблоны (PM1, сумка) сохраняются.
- ChecklistCatalog.duty: оригинальные 10 пунктов владельца, разбитые на 4 страницы; редактирование, reorder, JSON шаблонов — прежние.
- ChecklistRunRow + три nullable поля staffIdSnapshot, staffNameSnapshot, dutyDate. Room **9→10 только ALTER TABLE**, не destructive migration; старые строки без имени остаются читаемыми.
- Один шаблон, каждый новый запуск — новый Run (immutable snapshot пунктов); имя мастера из `StaffRepository` привязывается к дежурству на момент создания; дата локальная `Asia/Almaty`. Старые проверки не меняются при переименовании профиля.
- «Скопировать отчёт», системное меню «Поделиться» для самостоятельной отправки WhatsApp/Telegram. Не отправлять автоматически. Отчёт доступен при частичном прогрессе и сохраняет замечания по блокам.
- Не утверждать время фактического прихода или кадровую регистрацию из галочки. Проверки печей без операций растопки/управления; содержание и полномочия подлежат согласованию с Юрием.
- Установка отдельным package `kz.paritm.p26duty.preview`; не удалять P2.6 и другие тестовые APK, межпакетный перенос старой базы не выполняется.

## QA Xiaomi 13T Pro
1. В «Моя смена → Чек-листы» третья карточка «Дежурство» — 4 страницы, 2+2+4+2=10 пунктов. В конце страницы системная Android Back возвращает на предыдущую страницу без сброса.
2. Выбрать профиль мастера. Отметить 7/10, ввести замечание о неисправности, выйти из приложения и открыть снова: прогресс и заметки сохранены.
3. Нажать «Скопировать отчёт», вставить текст в WhatsApp/Telegram (не отправляя реальным адресатам без проверки). Сверить дату, имя, 10 пунктов, 7/10, статусы каждой проверки и замечания. Проверить Share.
4. Завершить дежурство с замечаниями, открыть из истории. Запустить новое — 0/10, прежний отчёт доступен. Изменить имя мастера или сам шаблон — прежний отчёт не меняется.
5. Проверить другой профиль: отдельное активное дежурство, история с исходными именами.
6. Проверить обновление Room 9→10 на существующей тестовой БД **в отдельном контролируемом сценарии**; штатная новая установка использует отдельный package, поэтому сама по себе не доказывает миграцию.
7. Регрессия: сумка, приёмка PM1, JSON export/import, LIGHT (2 и 6 гостей), GRAND, PREMIUM, «+ Процедура», «+ Событие», REOPEN, пять программ, журнал и Telegram.

## Принципиальные ограничения
- Дежурство пока **не связано с календарём смен и кадровым журналом**. 10:00 — исходный текст пилотного пункта, не факт автоматически зафиксированного прихода.
- Шаблон пока пилотный до согласования с Юрием порядка контроля печей и обязанностей.
- CI запускает JVM и компилирует AndroidTest APK, не проводит физический тест на Xiaomi.
- PR draft, не сливать с main до принятия владельцем. Безопасный откат — оставить предыдущие установленные приложения.
